# معماری «دخل‌وخرج من»

## نمای کلی

```
 آیفون (Safari / PWA نصب‌شده)            لپ‌تاپ ویندوزی
┌──────────────────────────┐        ┌───────────────────────────────┐
│ React UI                  │        │ Node.js (Express)              │
│ IndexedDB (Dexie)         │ HTTPS  │  ├─ سرو فایل‌های PWA (همان مبدأ) │
│  ├─ transactions          │◄──────►│  ├─ /api/sync  (push/pull)      │
│  ├─ categories / settings │  LAN   │  └─ SQLite ← D:\DakhlKharj\data │
│  └─ outbox (صف تغییرات)   │        │ پشتیبان زمان‌بندی‌شده → پوشهٔ دلخواه│
└──────────────────────────┘        └───────────────────────────────┘
```

* **آفلاین‌اول:** هر تغییر ابتدا در IndexedDB و صف `outbox` نوشته می‌شود؛ رابط کاربری هرگز منتظر شبکه نمی‌ماند.
* **یک مبدأ (Origin) واحد:** سرور لپ‌تاپ هم برنامه را سرو می‌کند و هم API را؛ بنابراین CORS، محتوای ترکیبی (Mixed Content) و چند گواهی لازم نیست.
* **منبع حقیقت:** پایگاه SQLite روی لپ‌تاپ؛ هر دستگاه یک نسخهٔ کامل محلی دارد.

## قرارداد داده

| فیلد | قالب | توضیح |
|---|---|---|
| `id` | UUID v4 | روی دستگاه ساخته می‌شود؛ کلید یکتا و پایدار در همهٔ دستگاه‌ها |
| `amount` | عدد صحیح مثبت | تومان |
| `date` | `YYYY-MM-DD` میلادی | فقط تاریخ، بدون منطقهٔ زمانی؛ نمایش شمسی فقط در UI |
| `createdAt` / `updatedAt` | ISO 8601 (UTC) | |
| `version` (مرحلهٔ ۴) | عدد صحیح | با هر تغییر روی سرور افزایش می‌یابد |
| `deletedAt` (مرحلهٔ ۴) | ISO یا null | حذف نرم (Tombstone) تا حذف‌ها هم همگام شوند |

## طرح همگام‌سازی (مرحلهٔ ۴)

1. **Push:** دستگاه عملیات صف را با `opId` یکتا و `baseVersion` می‌فرستد. سرور `opId`های پردازش‌شده را نگه می‌دارد ← ارسال مجدد بی‌اثر است (Idempotent).
2. اگر `baseVersion` با نسخهٔ سرور برابر نباشد ← **تعارض**: هر دو نسخه نگه داشته می‌شوند و کاربر انتخاب می‌کند. هیچ داده‌ای بی‌صدا حذف نمی‌شود.
3. **Pull:** دستگاه تغییرات پس از آخرین `cursor` (شمارندهٔ یکنواخت سرور) را می‌گیرد.
4. زمان‌های اجرا: باز شدن برنامه، بازگشت به برنامه (`visibilitychange`)، رویداد `online`، تایمر هنگام باز بودن، و دکمهٔ «همگام‌سازی اکنون». همگام‌سازی پس‌زمینه در iOS وعده داده نمی‌شود (Background Sync API در Safari پشتیبانی نمی‌شود).

## امنیت (مرحلهٔ ۳)

* سرور فقط روی شبکهٔ خصوصی (پروفایل Private فایروال ویندوز) گوش می‌دهد.
* HTTPS با گواهی محلی (mkcert) — بدون سرویس خارجی.
* ورود با یک گذرواژهٔ شخصی؛ ذخیره به‌صورت هش scrypt. هر دستگاه یک توکن تصادفی بلند می‌گیرد (روی سرور هش‌شده، قابل ابطال).
* اعتبارسنجی همهٔ ورودی‌های API، محدودیت نرخ ورود، مسیر داده خارج از پوشهٔ سروشده.

## وضعیت پیاده‌سازی

| مرحله | وضعیت |
|---|---|
| ۱. رابط کاربری | انجام شد (به‌علاوهٔ اقساط و بدهی‌ها، انتخاب فونت) |
| ۲. ذخیرهٔ آفلاین | انجام شد: Dexie روی IndexedDB، لایهٔ `data/repo.ts` با اعتبارسنجی و تراکنش اتمی، خواندن زنده با `useLiveQuery` |
| ۳. سرور لپ‌تاپ | انجام شد: `server/` (Express + `node:sqlite`)، HTTPS با mkcert، نام mDNS، احراز هویت دستگاه‌ها، API نسخه‌دار تغییرات، اسکریپت‌های ویندوز |
| ۴. همگام‌سازی | انجام شد: `client/src/data/sync.ts` (علامت همگام‌نشده در outbox، pull سپس push، opId، تشخیص و حل تعارض)، `app/sync-context.tsx` (همگام‌سازی خودکار هنگام باز بودن برنامه) |
| ۵. پشتیبان، CSV، PWA | — |

### جداول IndexedDB (نسخهٔ ۱)

| جدول | کلید | ایندکس‌ها |
|---|---|---|
| `transactions` | `id` | `date`, `type`, `categoryId`, `updatedAt` |
| `categories` | `id` | `type` |
| `debts` | `id` | `direction`, `updatedAt` — اقساط داخل رکورد بدهی |
| `kv` | `key` | تنظیمات (`settings`) و نشانگر راه‌اندازی (`seeded`) |
| `files` | `key` | فایل فونت کاربر (ArrayBuffer) |

تم (روشن/تاریک) در `localStorage` هم نگه داشته می‌شود تا پیش از باز شدن پایگاه داده اعمال شود.

### مدل حسابداری بدهی‌ها

* مبلغ قرض/وام (در صورت انتخاب «وارد موجودی شود») مانده را تغییر می‌دهد اما درآمد/هزینه نیست.
* پرداخت اقساط از مانده کم/به آن اضافه می‌شود؛ اگر کاربر «در گزارش هم دیده شود» را انتخاب کند، به‌جای آن یک تراکنش هزینه/درآمد ساخته می‌شود (تا دوبار حساب نشود).
* اقساط «پیش از برنامه» روی مانده اثری ندارند.
* دارایی خالص = مانده − مانده بدهی‌ها + مانده طلب‌ها.

## سرور (مرحلهٔ ۳)

```
server/src/
├─ main.js         شروع: HTTPS روی 0.0.0.0:8443 (یا HTTP فقط localhost اگر گواهی نیست)، صفحهٔ راه‌اندازی :8080، mDNS
├─ app.js          Express: فیلتر شبکهٔ خصوصی، سرآیندهای امنیتی/CSP، API، فایل‌های برنامه
├─ auth.js         scrypt برای گذرواژه، توکن تصادفی دستگاه (فقط هش SHA-256 ذخیره می‌شود)، محدودیت تلاش ورود
├─ records.js      ذخیرهٔ نسخه‌دار + شمارهٔ تغییر سراسری (rev) + جلوگیری از تکرار با opId
├─ validate.js     اعتبارسنجی هر نوع رکورد
├─ db.js           SQLite (WAL، synchronous=FULL)
├─ mdns.js         پاسخ به پرسش‌های dakhlkharj.local
└─ setup-page.js   صفحهٔ راهنمای آیفون و دریافت گواهی ریشهٔ عمومی
```

### API

| مسیر | دسترسی | کار |
|---|---|---|
| `GET /api/health` | آزاد (شبکهٔ خصوصی) | وضعیت و نیاز به راه‌اندازی |
| `POST /api/auth/setup` | فقط از خود لپ‌تاپ، یک بار | تعیین گذرواژه |
| `POST /api/auth/pair` | گذرواژه (۵ تلاش در ۱۵ دقیقه) | ساخت توکن دستگاه |
| `GET /api/status`، `GET/DELETE /api/devices` | توکن | وضعیت، مدیریت دستگاه‌ها |
| `GET /api/changes?since=rev` | توکن | دریافت تغییرات پس از یک شماره |
| `POST /api/changes` | توکن | اعمال عملیات: `ok` / `duplicate` / `conflict` (نسخهٔ سرور برگردانده می‌شود، چیزی بازنویسی نمی‌شود) / `invalid` |

هر عملیات: `{ opId, collection, id, baseVersion, deleted?, data }`. حذف‌ها به‌صورت «سنگ قبر» (deleted=1) نگه داشته می‌شوند تا به دستگاه‌های دیگر هم برسند.

## همگام‌سازی (مرحلهٔ ۴)

* هر نوشتن در `repo.ts` داخل همان تراکنش IndexedDB یک علامت در `outbox` می‌گذارد (یک علامت برای هر رکورد؛ `seq` با هر تغییر بالا می‌رود و `opId` تازه می‌شود).
* دور همگام‌سازی: **pull** (تغییرات پس از `sync-cursor`؛ نسخه‌های شناخته‌شده نادیده گرفته می‌شوند) ← **push** (آخرین نسخهٔ محلی هر رکورد با `baseVersion` = آخرین نسخهٔ سروری که دستگاه می‌شناسد).
* پاسخ `ok`/`duplicate`: نسخه ثبت و علامت پاک می‌شود، مگر اینکه رکورد هنگام ارسال دوباره تغییر کرده باشد.
* `conflict`: اگر محتوا یکسان باشد بی‌صدا یکی می‌شود؛ وگرنه در جدول `conflicts` ثبت و از ارسال کنار گذاشته می‌شود تا کاربر یکی از «نسخهٔ این دستگاه»، «نسخهٔ دستگاه دیگر» یا (برای تراکنش) «هر دو» را انتخاب کند.
* زمان‌بندی: باز شدن برنامه، بازگشت به برنامه، رویداد `online`، ۲ ثانیه پس از تغییر، جابه‌جایی بین صفحه‌ها (حداکثر هر ۱۰ ثانیه)، هر ۳۰ ثانیه، و دکمهٔ دستی. همگام‌سازی پس‌زمینه وعده داده نمی‌شود.
* تنظیمات فونت مخصوص هر دستگاه است و همگام نمی‌شود. «حذف همهٔ داده‌ها» فقط روی همان دستگاه اثر دارد و اتصال را قطع می‌کند.
* هنگام اتصال (جفت کردن) وضعیت همگام‌سازی بازنشانی و همهٔ رکوردها علامت می‌خورند؛ رکوردهای یکسان با سرور بدون تعارض یکی می‌شوند.
